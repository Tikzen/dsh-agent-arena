# 界面本地化开发说明

## 原生语言来源

Agent Arena 使用 DSH 的 `@deepseek-ai/dsh-client-locale` 服务，不维护第二份语言设置。客户端注入 `locale`，在插件生命周期内注册 `agent-arena` 命名空间的中文和英文词典，并订阅原生语言变化；卸载时清理注册和订阅。

入口是 DSH 的 **设置 → 通用 → 语言 / Settings → General → Language**。当前支持 `zh` 和 `en`；语言设置的持久化由 DSH 负责。

## 文件职责

- `src/locales/zh.mjs`、`src/locales/en.mjs`：界面词典，两份文件必须保持键名和插值参数一致。
- `src/localization.mjs`：前后端共用的格式化与消息描述符；不依赖 React 或浏览器。
- `src/client/locale-store.mjs`：原生语言服务的注册、订阅与清理。
- `src/client/i18n.ts`：React 订阅、文案渲染、错误描述符和界面模板标签。

## 添加文案

1. 为中英文词典添加相同键名。完整句子应使用一个键，不要拼接语言相关的句子片段。
2. 动态值使用 `{name}` 一类占位符，两份词典中的参数名必须一致。不要递归解释插值内容。
3. 客户端在渲染时使用 `t(key, params)`，不要在模块初始化时缓存翻译后的标签。
4. 需要保存在表单状态里的提示使用 `notice(key, params)`，渲染时使用 `errorText()`，使正在显示的提示也能切换语言。
5. 服务端生成的系统通知使用 `uiMessage()`；错误使用 `uiError()`，通过 `errorI18n` 返回描述符。原始中文消息继续保留，以兼容已有调用方。

## 内容边界

只翻译插件界面与插件自己生成的提示。**不要翻译或改写**角色名称、人格、预设对话、AI 指令、用户/模型消息、任务/方案内容、文件路径或供应商原始错误。

系统记录可以附带 `i18n` 描述符，角色动作状态也可以附带对应描述符。明确来自 AI 的原文可使用 `null` 标记，避免被旧版提示兼容逻辑误识别。旧记录仅对可精确识别的插件固定提示提供兼容翻译，无法可靠识别的动态文本保留原文。

## 验证

运行 `npm run build` 和 `npm run check`，检查词典键名、插值参数、引用完整性、原生订阅清理及错误描述符等测试。

浏览器还需验证：

- 在原生设置里中英文来回切换，主页入口和会话内嵌入口同时更新。
- 已填表单和已经显示的校验错误能够切换语言，不丢失草稿。
- 刷新后继续跟随 DSH 保存的语言。
- 桌面与窄屏的长英文标签不遮挡按钮；聊天、板块和底部操作可访问。
- 不发送模型请求，也不修改真实角色或聊天内容即可完成大部分本地化检查。
